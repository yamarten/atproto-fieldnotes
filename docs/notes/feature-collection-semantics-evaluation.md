# 機能とcollectionの対応：自動評価の比較と反例

[TODOのatproto利用の自動判別](../developer/todo.md#atproto寄与度と紹介候補の順位)で、主機能が何を読み書きするかを人が原文とschemaから照合する負担を減らせるか検討するための資料です。機能の説明とcollection定義をLLMで照合する案を中心に、利用範囲の総括・操作抽出の試行で分かった限界も記します。紹介候補の順位そのものの比較は[選定品質](promotion-selection-quality.md)に分けています。

機能原文とschema説明を一組ずつLLMで照合する方式は、2026-09-23の比較で通常調査への追加を不採用としました。正しく照合できる例はありますが、購読を注釈、表示設定を文書本体と同一視する誤りが残り、人による再照合を省ける品質ではありません。誤りが多数派、作業時間が純増、全方式が不可能と確認した結果ではありません。

利用範囲のLLM総括・短い原文からの操作抽出も通常採用していません。現行は[材料表示](../developer/specs/investigation.md#atproto利用の関連記述)と理由付き手動判断で、追加のLLM呼出しはありません。自動評価で負担を減らす目標を、手動annotation追加へ置き換えません。

## 再検討で外せない反例

| 対照 | 観測と問題 |
| --- | --- |
| Glean購読／`at.glean.subscription` | 公式READMEの購読PDS保存と単一RSS購読の定義は妥当な照合候補。名前のない原文から確認先を絞る利点はあるが、このcollectionの実利用確定とは別 |
| rolldプレイ／`at.rolld.play` | 原文にcollection名があり、既存の名前一致でも照合できる。追加判定の利益は小さい |
| Glean購読／`at.glean.annotation` | 原文 `Your subscriptions live as records on your PDS.` と定義 `Reading note on a specific RSS article.` を正確に引用しながら「購読はRSS記事への注釈」と誤説明。引用一致では拒否できない |
| Glean日次要約／annotation、mathr計算練習／個人backup用score | 同じ記事・得点という話題から機能本体と補助データを同一視。一般規則の明確化後も残る |
| Leafletテーマ／document、standard.site本文／theme・subscription | 表示設定・購読と文書本体の役割を混同 |
| Squire | actor recordの存在からタスク保存は分からない。別の操作抽出実験では「優先順位付きの一日を生成する」をstoreと誤読し、引用検査を通過 |
| scopeだけ、未使用・将来予定、汎用noteの構成例 | 権限をwriteと読む、非利用条件を落とす、textで表現可能というだけで定義との対応を補う誤り |

意味対応の比較は既存Qwen 3.6、推論none要求、最大512 tokenで、Codexが選んだ実資料23組・構成6組、計42成功requestです。候補の自動選抜を測った実験ではなく、暫定参照は人間goldではありません。全入力・prompt・出力は利用者了承により破棄済みで、上の代表例以上を再採点・完全再実行できません。実在対象での未使用確認、未知projectへの一般化、人の確認時間は未検証です。

## 再開条件と未決の設計

- 機能と実際のcollectionアクセスを結ぶ主体・対象・条件を、原文または実装経路で確認できること。scopeは宣言、recordは作成アプリ不明、schemaは定義であり、実利用の代用にしません。コードのない対象も非利用と断定しません。
- 上記反例と対応不足・実在対象の未使用確認例を固定し、正しい箇所を探す手間と誤提案の訂正負担を比較すること。同じpromptへの注意書きだけを反復しません。
- 利用深度、Bluesky用途、読取り／書込み、技術的な学び、既存寄与度の責務を分けること。読取り中心を一律減点する案や、現行手動roleを完成した観測schemaとする設計は未採択です。
- OAuth `include`は別の未解決事項です。解決するなら公式の権限セット仕様に従い、取得数・再帰・時間を制限する観測契約を先に定めます。未解決宣言から「書き込まない」を確定せず、公開読取りをscopeの有無で判定しません。

前段の総括／操作抽出の実験も、このcheckoutに全入力・出力は収録していません。再開時は上記の反例を現在の公開資料で確かめ、比較入力を新たに固定します。追加実験・実装の着手は未決です。

## この資料の役割が終わる条件

意味対応の自動評価を採用するか、追加しないと決めた時に、必要な理由を仕様・TODOへ反映して閉じます。評価を続ける場合も、引用は正しいが意味が違う例、補助データとの混同、権限宣言と実利用の混同を新しい評価素材に引き継げば、旧比較は削除できます。関連するOAuth観測など別課題の解決を待つ必要はありません。
