中心の価値は、紹介候補を拾い、紹介活動や後日の再利用に役立つ理解を、無理のない負担で蓄積できることです。文面の修正箇所数だけでなく、用途ごとに何を得られるかと、原文確認・情報の補完・誤認の訂正までの負担を比べます。詳しい説明ほど良い、欠落があれば悪い、確認先を絞れなければ無価値、とはしません。

利用者が最優先としたのは、紹介したい対象の取りこぼしと、ノイズが多すぎて対象が埋もれることの両方を避けることです。機能説明の誤りは、まずその選定への影響、その次に紹介文の下敷き・再利用時の負担として評価します。対象を増やすだけでも、保留を増やして誤りを避けるだけでも達成になりません。横断して使う手順は[実用上の評価原則](../developer/workflows/llm-model-evaluation.md#実用上の評価原則)へ反映しました。

### 欠落の発見と補完

「他の材料で補える」は、そこに材料があるだけでは成立しません。通常の確認で到達でき、何を補うべきか気づけることが必要です。現行Webの`editProfile`は既存文の編集欄と更新案、展開可能な根拠本文を同じdialogに出します。案を読み込むと編集欄は案へ置き換わり、プレビューで変更前後を確認できます。欠落の自動警告はありません。これはコード読取りで確認した導線で、今回の実browser操作や負担測定ではありません。説明専用案も通常導線へは未接続です。

### 採否と再開条件

- **現行方式**: 既存運用は暫定維持、最優先の選定品質については追加根拠が必要。説明は人が確認する更新案として扱う。機能変更例には紹介の下敷きとなる材料があるが、終了例の誤断定・時制混在は残る。既存の採用状態と品質合格を区別し、現状維持を無条件の正解にしない。
- **説明専用案**: 通常方式の置換には追加根拠が必要。現在の用途・終了状態を伝える改善は評価し、一般的なPDS保存の欠落だけを一律の不採用理由にしない。一方、紹介文の下敷きとして材料が減る不利はある。現行案と比べ、紹介対象の位置づけを保ち、紹介内容を組み立てる負担を減らすかは未確認。修正が一文で済むことだけでは限定試用の根拠とせず、試用は未承認。
- **共通prompt整理案**: 今回の構成は通常採用しない。終了例の根拠外断定が反復し、機能変更でPDS欠落と非使用断定が加わる。見出し改善だけで置換を支持しない。

評価原則と再評価の方向は暫定方針として利用者了承済みで、workflowへ反映しました。次の作業の優先順は母艦で判断します。現段階では説明の完全性を上げるための追加生成より、関心の高い既知対象が現行一覧へ届くか、候補間の優先差がPromotionの表示順へ妥当に反映され、普段見る範囲を何が占めるかを、保存済み材料から確認する方が目的に近いと推奨します。先頭候補だけのレビューで取りこぼしを測らず、既知の高関心対象側からも照合します。これは母艦へ渡す次作業の判断材料で、roadmapの変更や新しい監査の実行済み報告ではありません。個別事例は誤りの作用を確認する材料で、方式全体の有用性を決める代表標本ではありません。
