# 説明更新の品質評価・再開条件

現行運用を暫定維持し、説明専用案への置換には追加根拠が必要です。共通prompt整理案は通常採用しません。2026-09-23の再評価では、旧PDS設計の欠落だけで説明専用案を不採用にする根拠は不十分と判断しましたが、選定・紹介準備の改善も未確認です。この方向は利用者了承済みで、追加実験・実装・本番適用の承認ではありません。

評価する用途と優先順は[brief](../brief.md)、判断方法は[実用上の評価原則](../developer/workflows/llm-model-evaluation.md#実用上の評価原則)を使います。説明の完全性より、紹介候補の取りこぼし・埋没と、紹介文の下敷き・後日の再利用における補完・訂正負担を見ます。現行方式にも同じ基準を適用します。

## 再評価に使う対照

以下は架空素材の固定入力と実出力による比較です。行動・負担はCodexの推定で、利用者の実測や実在対象全体の精度ではありません。

| 素材 | 現行・候補の違い | 再開時に判断すること |
| --- | --- | --- |
| Reading Loomの終了 | 現行は旧機能の現在形と根拠のない「後継は存在しない」を残す。専用案は終了を明示するが、旧機能の利用者PDS保存が2反復とも欠落 | 触れる状態の誤認を減らす利点と、紹介材料を補う負担を比較。定義公開だけで共有仕様や技術的価値を確定しない |
| Reading Loomの機能変更 | 現行summaryは旧PDS設計と現在の検索を分けるがtaglineは旧機能。専用案はtaglineを直す一方、旧設計を省く | 見出し訂正と旧設計の補完のどちらが用途に効くか。修正数だけで方式を決めない |
| Workshop Atlasの部分終了 | 専用案は現行カタログとbrowser内CSV処理を保持するが、旧予約の利用者PDS保存を曖昧化し「代わりに」と置換を示唆 | 現在の用途を理解できる効果と、過去の技術を紹介する時の補完を分ける。現行との直接比較は未実施 |

共通prompt案では根拠外断定が反復し、機能変更で旧技術の欠落と非使用断定も加わりました。一時障害の不正な種別・架空根拠IDは保存側で拒否され元文面を保持したため、出力種別の改善を利用者の訂正時間削減とは数えません。根拠IDが正しくても不適切な文面はautomatic条件で保存され、保護条件では更新案として残ります。

## 既存説明と確認導線

2026-09-14の正本監査では4,811件すべてが編集来歴未記録の保護対象でした。旧LLM出力と現文面の一致・不一致から作者を推定せず、全件自動更新を解禁しません。個別訂正の対象と正本適用は未決です。具体例には、SpaceHost（`proj:0629779c6c2c`）の現在形のPDS hosting説明と終了・archiveのfeaturesの併存、osprey-atproto（`proj:61fd840868b8`）の技術説明とarchive情報があります。終了時期や作者は未確認で、archiveを価値消失と同一視しません。

Webの更新案と根拠本文・変更前後previewから確認できますが、欠落の自動警告はありません。「別の材料で補える」は、通常導線で到達でき、何を補うかに気づける場合に限ります。導線はコード読取りによる確認で、訂正負担を測っていません。説明検索は現在の通常経路へ接続済みですが、それだけで生成方式の改善効果を確認したことにはなりません。

## 素材と再開条件

[比較素材README](../../tests/fixtures/project_registry/description-refresh-evaluation/README.md)に原文・prompt・18出力・適用結果・通信なし再検証の入口があります。通常triageと説明専用案は入力・出力・suffixも異なり、タスク分割だけの因果効果は分離できません。全素材は既知となっており、次の確認には未使用素材が必要です。これより前の実観測による監査・8出力は本corpusに収録していません。

再開時は改善する用途、減らす確認・補完・訂正、未使用素材と反復、追加request・時間・費用の上限、停止条件と戻し方を提示して了承を得ます。サービス／共有Lexicon、個人用途、触りやすさ、特異なインフラ・分散性への役割を扱い、終了・機能変更の難例だけで全体を評価しません。欠落と誤断定の両方を見て、すべてunknown／変更なしを高評価にしません。

説明専用案は通常導線に未接続で、限定試用も未承認です。保存保護の検証は文章品質の合格ではなく、原文確認・訂正負担や通常enrich全体の追加費用は未測定です。
