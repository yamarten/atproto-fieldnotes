# Promotion再発見導線の運用評価

Promotion再発見導線と、通常一覧・技術候補・保留・Lowered・すべての速度改善は実運用Webへ反映済みです。

## 次に行うこと

2026-09-23の正本5,054件・active 3,382件の複製DBで、認証付き通常HTTPを各view 3回（limit 50、offset 0、personal tool除外）測ると、重複除去後も通常一覧約3秒・すべて約5秒が残り、主因は完全runtime viewの復元でした。cold測定・複数client負荷試験ではありません。日常利用を妨げる場合に、現在のデータと同時収集条件で再計測して次の改善を判断します。詳細の非同期マージ解析では別に6.2〜6.9秒を観測し、今回の最適化対象外です。request間cacheや推薦projectionは未導入で、必要性を先に確認します。

通常利用では、見慣れた候補の占有を解消できるか、保留の明示操作が負担にならないか、Lower priorityの理由検索で特集候補を回収できるかを評価します。明示操作が使われず占有が続く、情報不足の候補が依然上位に残る、理由検索では特集を組めない、のいずれかが分かった時は、[roadmapの紹介候補改善](../roadmap.md#atproto寄与度と紹介候補の順位)を再開します。

## 判断時の注意

品質scoreと受動的な非採用による減衰は変更していません。未見・根拠変化は有用性の保証ではなく、上位での長期非採用も未紹介全体を負例にする根拠ではありません。featuresの言い換えによる再提示と、未収集の変化の見逃しは残ります。現在値による紹介実績分析を過去時点の推薦精度とは扱いません。

現行の選択理由・契約は[評価仕様](../developer/specs/project-evaluation.md#紹介候補の表示順位保留)、保存形は[Project record](../developer/specs/project-record.md#promotionの確認記録)、操作は[Web UI](../user/web-ui.md#レビュー)を参照してください。応答速度と評価の残件を解消したら、この文書とstatusからの参照を整理します。
