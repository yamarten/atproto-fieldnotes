# 説明更新の運用前確認

説明更新と観測時点の実装は、固定入力による保存契約・判定規則と開発DBのWeb操作で確認しています。以下は実運用の品質・適用範囲を判断するために残る確認です。現行契約は[Project評価](../developer/specs/project-evaluation.md)を正本にします。

- 実LLMによる`description_change`の生成品質は未確認です。終了告知、機能変更、元の誤記、一時障害を含む固定素材で通常triageを実行し、根拠IDの適合だけでなく、用途・技術的価値の保持と時制を人が確認します。固定したLLM出力を適用するunit testとは区別します。
- 2026-09-14の正本DBに対する読み取り専用SQLite接続は、昇格後も`unable to open database file`で失敗しました。原因は未確定です。既存profileの分布や個別の説明内容を監査したことにはしていません。接続条件を確認したうえで読み取り専用のsample確認を再開します。来歴不明の既存説明は保護側に置き、作成者・観測日時を推定で補いません。
- service監視の30日・上限20 URLは初期値です。実URLでの取得負荷、失敗率、期限到来件数を確認してから頻度を判断します。開発DBの実preset確認は期限到来URLがない条件で行っており、外部取得を含む運用確認は未実施です。

正本DBへの適用・全件再調査・実運用のpreset有効化はこの変更に含めていません。これらを行う場合は、適用内容を確認して別途承認を得ます。確認が済んだ項目はstatusへ反映し、この保留から除きます。
