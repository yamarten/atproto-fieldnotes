# Core Overhaul Backlog

この文書はschema v2移行期に作成した作業用・仕分け用の履歴メモです。
現行仕様でも現行backlogでもありません。項目の一部は既に実装済みで、状態更新は行いません。
現在の実装状況は[status.md](../status.md)、未完了候補は[roadmap.md](../roadmap.md)を参照してください。

schema v2、調査pipeline境界、application service分割が入った後のcore側について、今のうちに壊して直せる前提で広めに棚卸しした候補です。恒久仕様は[project-record.md](../project-record.md)、[investigation-model.md](../investigation-model.md)、[background-jobs.md](../background-jobs.md)、具体的な現行heuristicは[registry-internals.md](../registry-internals.md)を正本とします。

## 優先度の目安

- P0: 今やると後続実装がかなり楽になる基盤整理
- P1: 調査精度・運用効率に直接効く
- P2: あると強いが、後回しでも大きくは詰まらない
- P3: 実験・将来拡張。必要性を見てからでよい

## P0: Runtime modelをv2へ寄せ切る

- canonical project dict fieldの棚卸し
  - 現状はcollector/evaluation互換のため`primary_nsid`, `bluesky_handles`, `tangled_handles`などflat fieldが残る
  - 保存正本ではなくruntime viewであるものを明示する
  - 残すfield、削るfield、helperでのみ導出するfieldを分ける
- runtime view builderを明示する
  - DB row + identifiers + relations + decisions + stateを、collector/evaluation向けviewへ変換する関数を一本化
  - 各moduleが勝手にdict shapeを仮定しないようにする
- `state_json` fieldの責務を整理する
  - 正本ではない補助fieldだけに限定
  - identifier/relation/decisionが混ざらないことをテストで固定
  - `ops`と`evidence`の内部fieldを必要最小限に分類
- derived helperの縮小
  - `service_url_candidate_values()`
  - `provider_repo_url_values()`
  - `resource_url_values()`
  - `source_code_url_values()`
  - 互換のためだけに残るhelperを、呼び出し元を直して減らす
- `prepare_project_view()`の役割を分割
  - UI/CLI表示用
  - evaluation用
  - merge/search用
  - すべてを1つの巨大viewにしない
- project dict mutation APIを限定する
  - identifier追加/削除
  - relation追加
  - decision反映
  - profile/state更新
  - 直接list fieldを触る経路を減らす
- mutation結果のinvariant check
  - removed compatibility fieldが復活していない
  - blocked/deferred identifierがcandidateに戻っていない
  - primaryが複数ない
  - profile/stateに移動済み正本が混ざっていない
- schema version checkの入口を整理する
  - CLI
  - Web
  - migration
  - tests
  - 旧DBを通常起動で読まないことを一箇所で保証
- old decoderの隔離
  - v1/v2 migration用decoderを通常storageからさらに離す
  - 通常readerに旧schema互換が戻らないようにする
- dataclass / typed modelの導入範囲を決める
  - 全projectをdataclass化するか
  - identifiers/relations/decisions/evidence/jobsだけtypedにするか
  - dictを残すなら境界でだけ型を強くする
